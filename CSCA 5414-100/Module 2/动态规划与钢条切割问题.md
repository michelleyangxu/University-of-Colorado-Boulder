# 动态规划与钢条切割问题

## 一、什么是动态规划

动态规划(Dynamic Programming, DP)是算法设计里非常重要的一类技巧,广泛用于最短路径算法、计算生物学等领域的问题。"Programming"这个词在这里沿用的是早期(20世纪40-50年代)的含义,更接近"规划/决策安排",而不是现在说的"编程"。DP 主要用来解决一类**优化问题**(求最大值或最小值)。

## 二、引入案例:钢条切割问题(Rod Cutting Problem)

**问题设定**:你是一家卖钢条的公司,标准原料是长度 $L$(比如 $L=10$米)的钢条,但市场上只能按特定长度出售(比如3米、4米),每种长度对应一个价格(如3米卖 \$1.80,4米卖 \$2.00)。问题是:**如何切割这根10米长的钢条,使卖出去的总收入最大?**

**举例对比几种切法**:

| 切法 | 浪费 | 收入 |
|---|---|---|
| 4米 + 4米 | 2米 | \$4.00 |
| 3米×3段 | 1米 | \$5.40 |
| 3米×2段 + 4米×1段 | 0米 | \$5.60 ← 目前最优 |

这类问题的核心特征是:**在若干种选择里,寻找使某个目标(这里是收入)最大化的方案**。

## 三、核心概念:最优子结构(Optimal Substructure)

动态规划最关键的思想是"最优子结构",包含三个要点:

**1. 问题需要一系列(sequential)决策,而不是一次性决策**

切割10米钢条不是"一步到位"的单一决策,而是可以看成:先决定第一刀切多长(比如切4米),再对剩下的部分(6米)重复同样的决策过程。

**2. 一旦做出当前决策,剩下的子问题和原问题结构完全相同(只是数据变小)**

比如切掉4米后,拿到2美元收入,剩下6米的钢条——这个"如何最优切割6米钢条"的问题,和最初"如何最优切割10米钢条"的问题**是同一类问题**,只是输入规模变小了。

**3. 最终的最优解,等于"当前决策的收益" + "子问题的最优解",两者结合**

以10米为例:如果最优做法是先切4米(赚\$2.00),那么剩下6米的最优切法(切成两段3米,赚\$3.60)加上这\$2.00,正好等于10米问题的最优解\$5.60。**子问题必须是最优地被解决,再和当前决策组合,才能得到原问题的最优解**——这是最优子结构成立的关键。

如果一个问题同时满足这三点,就说它具有"最优子结构性质",这时候就应该考虑用动态规划来求解。

## 四、把钢条切割问题形式化

**输入**:钢条总长 $L$;价格表 $(l_1,P_1),(l_2,P_2),\dots,(l_n,P_n)$(每种可售长度对应的价格)

**目标**:把长度 $L$ 切成若干段(每段长度取自 $l_1,\dots,l_n$,允许有浪费),使总收入
$$n_1P_1+n_2P_2+\cdots+n_nP_n$$
最大化(这里 $n_i$ 是切出长度 $l_i$ 的段数)。

**输出**:①最大可能收入是多少;②如何切割才能达到这个最大收入。

## 五、动态规划求解的第一步:识别最优子结构

对长度为 $L$ 的钢条,当前可以做出 $n$ 种决策之一:选择切下长度 $l_1,\dots,l_n$ 中的某一个。如果选择切下 $l_1$,立即获得收益 $P_1$,同时留下一个长度为 $L-l_1$ 的子问题需要求解;其余决策同理。这就是这个问题的最优子结构。

## 六、第二步:写出最优值的递推关系(暂不考虑具体切法)

先只关注"最大收入是多少"这个数值,定义函数 $\text{maxRevenue}(L)$:

**边界条件**:
$$\text{maxRevenue}(0) = 0,\qquad \text{maxRevenue}(L) = -\infty\ (L<0)$$

(长度为0没有收入;长度为负在物理上不存在,所以人为定义为负无穷,便于后续统一处理)

**一般情况**:
$$\text{maxRevenue}(L) = \max\Big(0,\ \max_{i}\big(P_i + \text{maxRevenue}(L-l_i)\big)\Big)$$

这里的 $0$ 对应"直接放弃、把钢条当废料"这个决策选项(收入为0);其余每一项对应"切下长度 $l_i$,获得即时收益 $P_i$,再加上剩余部分 $L-l_i$ 的最优解"。

这条递推公式正是"最优子结构"的直接体现:要求长度 $L$ 的最大收入,就遍历所有可能的第一刀切法,对每种切法,把"当前决策的收益"和"剩余部分递归求出的最优收益"相加,取所有选项里最大的那个。

## 七、朴素递归实现的伪代码

```python
def maxRevenue(L):
    if L == 0:
        return 0
    if L < 0:
        return float('-inf')
    maxSoFar = 0   # 对应"直接放弃"这个决策

        maxSoFar = max(maxSoFar, price_i + maxRevenue(L - l_i))

```

## 八、埋下的伏笔:朴素递归效率很差

虽然这个递归确实能正确算出"最大收入是多少",但直接这样实现,运行效率会非常差——因为在递归展开的过程中,同一个子问题(比如 $\text{maxRevenue}(6)$)会被**反复重复计算很多次**。后续内容将具体说明这种"重复计算"的严重程度,并引出动态规划真正的加速手段(记忆化 / 自底向上填表)。
